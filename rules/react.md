# 화면 코드

- JSX 속성에 함수를 인라인으로 넘기지 않는다. 이름을 붙여 선언하고 넘긴다 - 속성 자리에 로직이 들어가면 무엇을 그리는지가 안 보인다. `map` 콜백은 예외.
- 조건부 렌더링에 `&&`를 쓰지 않는다. early return 이나 삼항을 쓴다 - 왼쪽이 0 이면 화면에 0 이 그려진다.
- `memo`, `useCallback`, `useMemo`는 이유를 주석으로 적을 수 있을 때만 넣는다. 이미 있는 것은 걷어내지 않는다.
- `page.tsx`와 라우트 컴포넌트는 데이터를 받아 view 컴포넌트에 넘기는 조립만 한다. 데이터를 가져오는 로직은 서비스 함수에 둔다.
- 목록의 페이지, 검색어, 필터는 URL 에 둔다 - 편집하고 돌아왔을 때 초기화되면 반복 작업이 끊긴다.
- `alert()`, `confirm()`을 쓰지 않는다. 다이얼로그는 직접 그린다.

## 폼

- 폼 상태는 한 곳(RHF 면 `useForm`)에 둔다. 필드 컴포넌트는 값과 핸들러만 받고 자체 상태를 갖지 않는다.
- 저장 버튼을 비활성화하지 않는다. 저장을 시도하면 무엇이 왜 막혔는지 보이고 첫 에러 필드로 포커스가 간다.
- 입력 중에 에러를 띄우지 않는다. 필드를 처음 벗어날 때부터 검증하고, 틀린 필드는 고치는 즉시 풀어준다(RHF 면 `mode: 'onTouched'`, `reValidateMode: 'onChange'`).
- 수정한 폼은 화면 안 이동과 새로고침, 닫기 두 경로 모두에서 이탈을 막는다.

## 스타일

- Tailwind 는 색, 간격, 포커스 링을 `@theme` 토큰 한 곳에 둔다.
- Emotion 은 스타일을 `*.styles.ts`로 분리하고, 변형은 객체 맵으로 두고, 특이성이 모자라면 `!important` 대신 `&&`를 쓴다.
