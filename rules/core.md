# 공통 - 판단 경계, 표기, git

- 요구사항이 정하지 않은 지점은 구현하지 않고 멈춘다. 선택지 2~3개와 각각 무엇이 깨지는지, 추천 하나를 낸다 - AI 가 정하면 그 판단이 기록에서 사라진다.
- 사용자가 고르면 `.claude/_workspace/<scope>/decisions.md`에 `- 빈틈 / 고른 것 / 이유` 한 줄을 붙인다. 이미 정한 지점은 그대로 따르고 다시 묻지 않는다.
- 같은 시도를 2회 넘게 반복하지 않는다. 2회 실패하면 문제를 하위 단계로 쪼개 제시하고 확인을 받는다.
- 정책 값(날짜 계산, 금액, 상태 전이, 필터 기본값, 권한)은 묻지 않고 바꾸지 않는다 - 코드에 적힌 숫자가 아니라 업무 규칙이다.
- 하지 않은 검증을 했다고 쓰지 않는다. "~일 것 같습니다", "아마" 대신 확인한 것과 확인하지 않은 것을 나눠 적는다.
- 라이브러리 추가는 `decisions.md`에서 정한 뒤 한다 - 규모에 맞는 선택인지가 판단 대상이다.

## 표기

- 한국어로 쓴다. 영문 단어와 숫자, 버전 뒤 조사는 한 칸 띄우고(`loader 와`, `16.4 부터`), 백틱 코드 뒤는 붙인다(`` `hooks/`에 ``). 단위 명사는 붙인다(`2회`, `50자`).
- 가운뎃점과 줄표를 쓰지 않는다. 하이픈 `-`를 쓴다. 이모지를 쓰지 않는다.
- 군더더기를 쓰지 않는다: `~를 통해`, `성공적으로`, `효과적으로`, `~인 것 같습니다` - 뜻은 없고 문장만 길어진다.

## git

- `git add -A`, `git add .`를 쓰지 않는다. 파일을 명시한다 - 의도하지 않은 파일이 섞인다.
- `git push --force`와 `git reset --hard`는 쓰지 않는다 - PreToolUse 훅이 막는다. 필요하면 사람이 셸에서 직접 실행한다. `--amend`와 `checkout --`는 지시가 있을 때만 쓴다.
- 커밋과 PR 어디에도 AI 표기(`Co-Authored-By`, `Generated with`)를 넣지 않는다.
- 커밋 메시지는 `/commit`이 만든다 - `type(scope): 요약`, type 영어, 요약 한국어 명사형.
- PR 제목은 커밋 제목 형식 50자 이내. 본문은 `## 작업 내용`(필수), `## 특이사항`(선택, 비면 섹션을 뺀다). "작업했습니다" 같은 서술형을 쓰지 않는다.

## 진입점

- 검토 `/check`, 린트 `/lint`, 커밋 `/commit`, 테스트 `/test-unit` `/test-integration` `/test-e2e`, 화면 `/web-design`, 계획부터 검토까지 한 번에 `/work`. 버그 사냥은 내장 `/code-review`, 정리는 `/simplify`.
