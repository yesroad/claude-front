# Test

## 종류 고르기

`$ARGUMENTS`를 읽는다. 없으면 `git status --porcelain`으로 방금 바뀐 파일에서 고른다. 사용자가 종류를 말했으면 그것을 쓴다.

- 순수 함수(검증, 변환, 정렬, 정책 계산) → `references/unit.md`
- 서비스, 쿼리, Provider, 폼 제출을 건너는 컴포넌트나 훅 → `references/integration.md`
- 화면을 오가는 사용자 여정 → `references/e2e.md`

고른 파일 하나만 읽는다. 렌더만 하는 컴포넌트와 스타일은 테스트하지 않는 편이 낫다고 한 줄로 알리고 끝낸다.

## 공통 절차

1. 환경 확인. 필요한 패키지가 없으면 설치할 목록을 보여주고 한 번 묻는다. 임의로 설치하지 않는다.
2. 시나리오. Given-When-Then 목록을 먼저 보여주고 합의를 받는다. 합의 전에는 코드를 쓰지 않는다. 5개를 넘으면 뺄 것을 함께 제안한다.
3. 작성. 합의된 시나리오만 쓴다. 형식과 단언 규칙은 `rules/testing.md`가 자동으로 붙는다. 기존 테스트 파일은 덮어쓰지 않고 빠진 시나리오만 추가한다.
4. 실행. 실패하면 출력을 그대로 보여준다. 통과시키려고 구현을 바꾸지 않는다. 같은 실패가 2회 반복되면 멈추고 사람에게 넘긴다.
5. 마무리. 덮은 것과 덮지 않은 것을 각각 한 줄로 알린다.
