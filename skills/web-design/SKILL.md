# Web Design

화면을 그리기 전에 레이아웃을 합의하고, 토큰을 먼저 정하고, 마지막에 QA 로 확인한다. 각 단계 사이에 사용자 확인이 있다.

## Workflow

1. 입력 수집. 요구사항, 참고 자료(피그마, 스크린샷, 기존 화면), 대상 사용자(운영자인지 고객인지), 기기(데스크톱만인지 모바일 포함인지)를 확인한다. 피그마 링크가 있으면 MCP 로 레이어와 토큰을 읽는다.
2. 톤 결정. 셋 중 하나를 추천하고 확인을 받는다 - 밀도 높은 운영 화면 / 여백 많은 소개 화면 / 콘텐츠 중심 읽기 화면. 톤이 정해져야 간격과 타이포 토큰이 정해진다.
3. 목업. `docs/<화면>-mockup.html` 한 장을 Tailwind v4 브라우저 빌드(`@tailwindcss/browser` CDN)로 만든다 - 색은 회색조, 실제 문구, 실제 데이터 모양. 레이아웃과 정보 우선순위만 합의한다. 브라우저로 열어 보고 확인을 받는다. 두 번 넘게 뒤집히면 요구사항이 덜 정해진 것이니 멈추고 묻는다.
4. 토큰. 구현 전에 한 곳에 정한다 - Tailwind v4 는 `@theme`, Emotion 은 theme 객체. 색은 배경 2, 텍스트 2, 강조 1, 상태(성공, 경고, 오류) 3 이내. 간격은 4px 배수. 포커스 링 1종. 폰트는 본문 1, 숫자가 많은 표면 `tabular-nums`.
5. 구현. 목업의 구조를 컴포넌트로 옮긴다. 레이아웃은 Grid 와 Flex, 반응형은 360px 부터 위로. 아이콘은 한 세트(lucide 등)만 쓴다.
6. QA. 아래 체크를 돌려 결과를 보여준다. 안 되는 항목은 고치기 전에 보고한다.

## QA 체크

- 360px, 768px, 1280px 에서 깨지는 곳이 없는가. 가로 스크롤이 생기지 않는가.
- 키보드만으로 모든 조작이 되고 포커스 링이 보이는가. 본문 대비 4.5:1 이상인가.
- `prefers-reduced-motion`에서 애니메이션이 꺼지는가.
- 한국어 - `word-break: keep-all`, 본문 줄 길이 최대 600px(한글 35~45자), 줄 간격 1.6 이상.
- 빈 상태, 로딩, 에러, 긴 문자열(이름 30자, 금액 10억)의 화면이 있는가.
- 이미지에 alt, 아이콘 버튼에 라벨, 상태 변화에 `aria-live`가 있는가.

## 한국어 화면 규칙

- 폰트는 Pretendard(또는 프로젝트 기본). 영문 전용 폰트를 한글 본문에 쓰지 않는다 - 한글 글리프가 없으면 시스템 폰트로 떨어진다.
- 금액은 세 자리 콤마, 숫자와 단위는 띄어 쓴다(`1,200 원`). 날짜는 `2026-10-15` 형식으로 통일한다.
- 데스크톱에서 햄버거 메뉴를 쓰지 않는다 - 메뉴가 5개 이하면 전부 보여준다.
- 버튼 문구는 동작 명사형(`저장`, `삭제`), 확인 다이얼로그는 무엇이 일어나는지 한 문장.

## 피할 것 - AI 가 그린 티가 나는 패턴

- 보라색 그라데이션 배경, 유리 효과(glassmorphism) 카드.
- 카드 안의 카드, 모든 요소에 같은 둥글기와 그림자.
- 이모지 아이콘, 가운데 정렬 남발, 의미 없는 히어로 문구.
- 데이터 화면에 여백 과다 - 운영 화면은 한 화면에 더 많은 행이 보이는 쪽이 낫다.
